# 程序化銀河地圖

## 狀態

本文件定義程序化銀河、恆星系統、航線、探索與地圖持久化系統。第一版無介面核心現已實作受限的確定性雙區域圖、不可變系統與星航道狀態、受知識限制的路線規劃、驗證、`World` 快照及存檔往返。作者定義的銀河內容、航行命令、旅行事件與 WPF 地圖仍在規劃中。已退役的確定性 4×4 遠征格網不得復活為平行原型；新的銀河功能必須繼續透過權威航行與持久化邊界。

可改變此圖形的可選後期戰役威脅見 [`Endgame_Crisis.md`](Endgame_Crisis.md)。航經路線時出現的種子化情境見 [`Events.md`](Events.md)。玩家可見戰役設定的歸屬與持久化規則見 [`GameSettings.md`](GameSettings.md)。

## 設計目標

- 以每個明確戰役種子產生不同但可重現的銀河。
- 以星團、長航線、瓶頸、危險捷徑、孤立區域與競爭陣營領地建立策略地理。
- 讓探索揭露有用知識，而非僅顯示圖示。
- 支援奧術與工業船艦，且兩種升級路線都不會無法穿越所產生的銀河。
- 將奧術研究地點、柴油龐克工業港，以及原子龐克反應爐設施做成作者撰寫的地點內容。
- 以作者內容配置星雲、以太潮汐、奇異世界、採礦帶、彗星帶與氣態巨星。
- 以新的組合安排既有系統定義與事件內容，不產生未審核的敘事文字。
- 對生成、尋路、可見性與每個模擬 tick 的工作量設上限。
- 在生成器或內容修訂時保留穩定身分與舊存檔。

本設計汲取大型程序化策略遊戲的吸引力，但採用本作自有的拓樸、術語、內容、陣營、宇宙觀與航行尺度模擬。精靈發現開放太空以太後開創奧術導航；矮人與地精科學家其後發展可重複的耦合技術。以太洋流與干擾使航線條件有意義，而工業船艦則經由同一銀河採取不同推進方式。

## 地圖階層

| 層級 | 職責 |
| --- | --- |
| 銀河 | 戰役種子、形狀、全域邊界、生成器版本與不可變拓樸 |
| 區域 | 用於生成、探索摘要、陣營與受限搜尋的空間分割 |
| 恆星系統 | 含一顆恆星或其他主要天體特徵的圖節點 |
| 星航道 | 連接系統的可通行圖邊，含距離、條件與危害 |
| 軌道 | 圍繞系統主體、用於配置世界、站點與地點的有序環帶 |
| 地點 | 可到訪的錨地、世界、衛星、遺跡、殘骸、聚落、資源區或異常 |

銀河地圖是一張圖。顯示座標提供穩定布局；船艦只能沿星航道或已明確解鎖的特殊路線移動，螢幕上的距離本身絕不構成相鄰關係。

## 銀河設定

生成會消耗經驗證的不可變設定紀錄：

| 設定 | 範例 | 規則 |
| --- | --- | --- |
| 規模 | 航程、小型、標準、大型、宏偉 | 選擇受限系統數與生成預算 |
| 形狀 | 螺旋、環狀、星團、破碎、開闊 | 選擇拓樸策略而非背景圖片 |
| 星航道密度 | 稀疏、普通、稠密 | 在連通性保證後調整受限的額外邊 |
| 危害盛行度 | 低、普通、高 | 調整合格危害權重，不讓必經路線必死 |
| 宜居地點盛行度 | 稀少、普通、豐富 | 調整可作為聚落的候選點 |
| 陣營存在度 | 稀疏、普通、擁擠 | 調整初始陣營數與領土壓力 |
| 古代活動 | 平靜、普通、甦醒 | 調整遺跡、封鎖路線與古代危害 |

規劃的系統數為 64、128、256、512 與 1,024。上限是作者定義的限制，而不是玩家可任意輸入的整數。第一個完整航程僅使用 16 系統測試區域；更大的預設值仍屬規劃，須先符合生成、繪製、存檔與尋路預算。

## 確定性生成流程

在生成器版本、內容修訂、設定與種子相同時，下列流程產生相同的不可變銀河：

1. 驗證設定，並衍生拓樸、系統、地點、陣營、危害與名稱等具名隨機串流。
2. 保留起始錨地及情境要求的作者系統。
3. 依選定形狀放置受限區域中心與整數顯示座標。
4. 以穩定序號 ID 和最小間距規則放置系統節點。
5. 以確定性生成樹連接每個系統。
6. 加入受限數量的可選星航道，創造環路、替代路線與可控瓶頸。
7. 指派系統主體、軌道數、環境標籤與系統種子。
8. 放置必要服務、宜居地點、資源、遺跡、異常、危害與罕見作者地標。
9. 選出陣營起源，透過確定性的受限圖擴張建立初始領土。
10. 依情境、船員與陣營背景計算探索提示及起始知識。
11. 在發布銀河前驗證可達性、路徑成本、內容參考、密度上限與起始區公平性。

驗證失敗時，生成器前進至受限的具名重試串流，絕不無限重試。用盡嘗試次數時回傳明確生成錯誤，並保持原有戰役或預覽不變。隨機串流獨立由戰役種子與穩定用途 ID 衍生；新增遺跡表不應悄悄重排整張星航道圖。在浮點差異可能影響排序之處，使用定義的整數或定點運算。

## 形狀與拓樸

| 形狀 | 拓樸特性 |
| --- | --- |
| 螺旋 | 多條彎曲旋臂以爭奪中的核心與偶爾的跨臂航線相連 |
| 環狀 | 強烈的環形航線，穿越中心的路線危險或稀少 |
| 星團 | 稠密的本地群集，以少數長距離星航道連接 |
| 破碎 | 不規則口袋、死路、斷裂的古代路線與高風險重連機會 |
| 開闊 | 分布均勻、環路較多、強制瓶頸較少的系統 |

每個普通銀河起初都連通。稀疏設定可以有橋與死路，卻不能有不可達的普通系統。封鎖系統與單向特殊路線是明確的內容例外，不列入普通連通性驗證。起始錨地至少有兩條可行外出路線，且至少一條回程不受任一可選遭遇單獨阻斷；生成不保證每條路線安全、有利或目前可負擔。

## 恆星系統與地點

系統摘要隨銀河拓樸生成；詳細地點則在感測器、星圖或旅行揭露時按確定性實體化。內容可包括：

- 單星、雙星、不穩定、死亡或人工恆星主體；岩質、海洋、氣態、冰凍、熔融、破碎或建造世界；
- 衛星、星環、小行星族、晶體淺灘與彗星軌跡；
- 港口、自由錨地、陣營站、修院、船塢與市場；
- 殘骸、廢船、戰鬥碎片、打撈聲索與求救訊號；
- 古代遺跡、封印金庫、廢棄閘門與帶文字遺物；
- 以太風暴、輻射區、靈能回響、重力剪切與掠食者；以及受明確合格條件約束的獨特作者系統。

系統生成先選擇相容的物理與超自然標籤，再選擇符合約束的作者定義；不可能的組合會被拒絕，而非靜默忽略。程序化配置絕不發明最終任務文案，而是選取已本地化的作者模板、參數、陣營、地點與後果。獨特地標具備最小距離、互斥與最大數量規則。

當地點產生敵對遭遇時，戰術布局與結果遵循 [`Battle.md`](Battle.md)。回到探索時，已開啟航線、失效防禦、損害、危害、回收物件與被遺棄角色都會保留。

## 星航道與旅行

每條星航道保存穩定端點 ID，以及下列作者或生成數值：路線距離與基礎旅行時間、燃料／推進劑／以太能量需求、已知與隱藏危害標籤、穩定度／洋流方向／季節狀態、最低導航或船艦能力需求、陣營控制／通行費／封鎖／法律限制，以及探索狀態與信心。

奧術流帆與工業推進器穿越同一張銀河圖，但以不同方式計算成本。奧術船可利用強以太洋流卻受干擾；柴油龐克與原子龐克船帶明確燃料或反應質量，並可較穩定地通過魔法死寂航線。任一途徑都不獨占所有航線；特殊優勢須有替代方案或可見代價。

路線規劃使用受限圖搜尋。玩家可按旅行時間、燃料、已知危險、通行費、隱密性或自訂加權策略最佳化。未知數值顯示為不確定性，不會秘密傳入規劃器；同成本選項以穩定系統 ID 作確定性破除平手。沿選定路線旅行會在已提交的進度點建立受限事件機會；合格性、種子化選擇、玩家決定與持久後果遵循 [`Events.md`](Events.md)。開啟銀河地圖或在暫停決策畫面等待都不會擲出事件。

## 探索與地圖知識

權威銀河獨立於船員知識存在。每個戰役記錄每個系統、星航道與地點的知識：

| 狀態 | 玩家可見意義 |
| --- | --- |
| 未知 | 沒有地圖項目 |
| 傳聞 | 知道可能的系統、航線或特徵，但身分或位置不確定 |
| 偵測 | 感測器確認存在與大略屬性 |
| 勘測 | 已記錄主要物理特徵、普通航線與危害 |
| 繪製星圖 | 導航資料與常見地點足以供有把握地規劃 |

個別事實還記錄來源、信心、觀測 tick 與是否過時。因此地圖可正確顯示系統，卻錯誤呈現其當前陣營、市場、封鎖或危害。駕駛操作船艦，星象導航規劃航線，感測器揭露遠方特徵，語言與讀寫解讀外國星圖，古代學識辨識過時航線與地標。船員可依政策共享、出售、比對衝突來源或保留發現。

## 陣營與變動太空

生成會建立陣營起源、初始聲索、已知聚落與爭議前線。領土遵循星航道圖，而非顯示座標周圍的圓形；配置遵守起源最小距離、宜居地點需求、必要中立空間與受限擴張預算。戰役建立後，陣營控制、戰爭、市場、站點、危害與航線通行權都是可變模擬狀態，載入存檔時不得重新生成。不可變的生成基線與後續已提交事件分開，讓 UI 能解釋銀河如何改變。

家園錨地起初中立或受明確作者保護者庇護。起始陣營不得封鎖所有出口，必要的早期服務也不得只置於敵對領土後方。

## 串流與模擬邊界

建立銀河時會產生完整節點與邊圖及輕量系統摘要。詳細地點、本地地圖、居民、貨物庫存與遭遇，會在首次需要時由儲存的系統或地點種子實體化；一經發布，持久變更即儲存而不再生成。只有活動系統與明確排程的遠端程序獲得詳細模擬 tick；其餘系統以受限彙總事件於記錄的提交邊界推進。開啟地圖、調整縮放或繪製遠方系統，絕不推進模擬或消耗遊戲隨機性。

生成與執行期上限包含：系統數、每系統星航道數、每系統地點數、陣營、地標、搜尋展開、生成嘗試與可見地圖標籤。容量失敗須回傳可操作錯誤或明確降級行為。

## 資料與持久化

不可變銀河標頭範例如下：

```json
{
  "schemaVersion": 1,
  "generatorVersion": 1,
  "seed": 731942,
  "settingsId": "galaxy.settings.voyage",
  "contentRevision": "content.prototype.1",
  "shapeId": "galaxy.shape.clustered",
  "systemCount": 16
}
```

穩定生成 ID 使用戰役 ID 與確定性序號，例如 `system.731942.0007` 與 `starway.731942.0007.0012`。呈現名稱由穩定的作者名稱片段 ID 生成並獨立本地化；翻譯名稱絕不可成為模擬身分。

已發布存檔保存維持地圖所需的不可變拓樸，以及種子、生成器版本、設定、內容修訂、探索紀錄與動態世界變更。新版生成器只建立新戰役，絕不靜默重寫既有銀河。任何壓縮或遷移都必須先驗證完整替代品再發布。內容載入拒絕重複 ID、無效權重、缺失定義、無界表、不可能配置約束、無效路線成本、孤立星航道與不可達必要系統；存檔載入則明確拒絕或遷移未知生成器版本及內容修訂。

## 第一個可玩範圍

第一個完整航程以一個明確種子與生成器版本，用 16 節點連通圖取代原型格網。它需要：

- 一個家園錨地與至少兩條初始外出星航道；
- 兩個區域、一個可見瓶頸與至少一條替代路線；
- 至少四種系統原型與六種地點類型；
- 三個陣營、一個聚落、一個中立市場與一個爭議地點；
- 一處遺跡、一處打撈點、一個以太危害與一個工業危害；
- 四個作者旅行事件定義，包含無事件結果，且每段航程不超過兩個事件；
- 未知、偵測、勘測與繪製星圖等知識狀態；
- 依時間、燃料與已知危險的確定性路線規劃；以及
- 存檔／讀檔保留拓樸、發現與已改變地點。

此切片的成功條件是：相同種子產生相同銀河；有限知識改變一個有意義的路線決定；重訪系統時看見已提交的後果，而不是重新生成的副本。更大銀河、銀河征服、每個系統的模擬人口、無縫行星地圖與無限制玩家自訂生成設定仍延後處理。
